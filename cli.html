Srin CLI Tool Reference

The Srin CLI (srin) is your command-line companion for scaffolding architecture, executing database migrations, inspecting registered routes, and running the local development server.

Overview & Usage

You can invoke the Srin CLI from the root of your project using srin <command> [options] (or php srin ...). To display the full interactive command list at any time, run:

Bash 
srin help

Command Matrix

Command Arguments / Flags Description
add controller <Name> [--mail] Generates a new controller inside Controller/ extending BaseController.
add model <Name> [-m] Generates a new ActiveRecord model in Model/. -m flag auto-creates a paired migration.
add migration <name> Generates a timestamped schema migration file in database/migrations/.
add checkpoint <Name> Generates a new linear request checkpoint inside Checkpoint/ extending Core\Checkpoint.
add command <Name> Generates a custom CLI command and cPanel cron job in Command/ extending Core\Command.
add seeder <Name> Creates a new database seeder class in database/seeders/.
add page <name> Generates a new view page in Pages/ connected to [connect 'layouts/main'].
add layout <name> Creates a new master layout file in Pages/layouts/.
add partial <name> Creates a reusable partial component in Pages/partials/.
add error <status_code> Scaffolds a customized HTTP error view (e.g. 403, 404, 500) in Pages/errors/.
migrate None Executes all pending database migrations in chronological order.
migrate fresh [--seed] Drops all tables and re-executes all migrations from scratch. Optionally runs seeders.
migrate rollback None Rolls back the last executed batch of database migrations.
migrate status None Shows database migration status: ran vs pending migrations.
seed [--class=Name] Runs database seeders to populate initial or test data.
init [--force] Configures .env with project name and generates secure 256-bit APP_KEY (runs automatically on composer create-project).
commands None Lists all registered custom CLI and cPanel cron commands discovered in Command/.
<custom-command> [args] Executes a custom CLI command or background cron task (e.g. srin send-weekly-digest).
links None Displays a clean formatted table of all registered route links from Routes/link.php.
dev [--port=8000] Starts the embedded PHP local development web server.
key [--force] Generates a cryptographically secure 256-bit encryption key (AES-256-GCM) and sets APP_KEY in .env.
logs [-f] [--lines=N] [--mail] Views formatted application logs with ANSI color-coded severity levels and live real-time tailing.
clear logs None Flushes application and mail logs in Others/logs/.
clear cache None Flushes compiled template view cache in Others/cache/views/.

Deep Dive: Generating Controllers

When creating a controller, Srin automatically appends the Controller suffix if omitted and scaffolds standard CRUD actions:

Bash 
# Generates Controller/ArticleController.php
srin add controller Article

# Scaffold a contact controller pre-configured with PHPMailer logic
srin add controller Contact --mail

Deep Dive: Generating Models & Migrations

You can generate an ActiveRecord model and its database table migration simultaneously using the -m flag:

Bash 
# Generates Model/Product.php and database/migrations/YYYY_MM_DD_HHMMSS_create_products_table.php
srin add model Product -m

Inspecting Registered Route Links

Ever wonder what route links are currently active or which controller action handles an endpoint? Use srin links to print the route table:

Bash 
srin links

+--------+------------------+--------------------+-----------------------------+
| Method | URI              | Name               | Action                      |
+--------+------------------+--------------------+-----------------------------+
| GET    | /                | home               | HomeController@index        |
| GET    | /docs            | docs               | DocsController@index        |
| GET    | /docs/{topic}    | docs.show          | DocsController@show         |
| GET    | /blog            | blog.index         | BlogController@index        |
| POST   | /contact         | contact.submit     | ContactController@submit    |
+--------+------------------+--------------------+-----------------------------+

Database Migration Management

Execute, rollback, and check migration progress seamlessly:

Bash 
# Run all pending migrations
php srin migrate

# Check migration history
php srin migrate:status

# Rollback the most recent migration batch
php srin migrate:rollback

# Wipe database, rerun all migrations, and seed fresh test data
php srin migrate:fresh --seed

Application Logging & Terminal Live Tailing

Srin Engine provides a built-in terminal log viewer via php srin logs. Logs are saved in Others/logs/ and automatically categorized with ANSI color-coded severity tags (ERROR in red, WARNING in yellow, INFO in green, and DEBUG in cyan).

Log File Locations

Log File Path Content Description
Application Log Others/logs/srin.log Uncaught server exceptions, system errors, database queries, and custom application logging via Core\Log.
Mail Dispatch Log Others/logs/mail.log Outgoing emails captured when MAIL_DRIVER=log is active in development mode.

Viewing & Live-Tailing Logs via Srin CLI

Bash 
# 1. View the latest application logs (default: last 25 lines)
php srin logs

# 2. Real-time live streaming / tailing (auto-updates as logs arrive; press Ctrl+C to stop)
php srin logs -f
# Or:
php srin logs --tail

# 3. View a custom number of lines
php srin logs --lines=50

# 4. Inspect outgoing mail delivery logs
php srin logs --mail

# 5. Clear / truncate all log files in Others/logs/
php srin clear:logs
# Or:
php srin logs --clear

Checking Logs with Native OS Terminals

If you prefer inspecting logs directly through your system's native terminal shell without invoking PHP:

PowerShell (Windows) 
# View and live tail the last 30 lines in PowerShell:
Get-Content Others/logs/srin.log -Wait -Tail 30
Bash / Linux / macOS 
# Live tail application log with standard UNIX tail:
tail -f Others/logs/srin.log

# View last 100 lines:
tail -n 100 Others/logs/srin.log

Scaffolding Checkpoints (Linear Middleware)

Checkpoints act as linear security gates before and after a controller action executes. Use the CLI generator to scaffold a new checkpoint class:

Bash 
# Scaffolds Checkpoint/VerifySubscriptionCheckpoint.php
srin add checkpoint VerifySubscription

Generating Encryption Keys (APP_KEY)

Srin Engine's authenticated encryption engine (Core\Crypt) and optional application peppering rely on a cryptographically secure 256-bit secret key. Generate or rotate your key with:

Bash 
srin key

This command automatically generates a 32-byte random binary key using random_bytes(32), formats it as base64:..., copies .env.example to .env if needed, and safely updates the APP_KEY entry.

Custom CLI Commands & cPanel Cron Jobs

Srin Engine empowers you to create custom command-line tools, batch data processing tasks, maintenance routines, and scheduled cron jobs that run seamlessly both in local development and on live cPanel hosting. Every custom command extends Core\Command and gains full access to database connections (Core\DB), models, configuration, mail transfer, and .env variables.

1. Scaffolding a Custom Command

Generate a new command using srin add command <Name>:

Bash 
srin add command SendWeeklyDigest

Srin automatically transforms the input into a StudlyCase class (Command\SendWeeklyDigest) inside Command/SendWeeklyDigest.php, creates a kebab-case command signature (send-weekly-digest), and displays the complete copy-paste cPanel cron job setup instructions.

2. Anatomy of a Command Class

Commands inherit built-in ANSI coloring methods, table formatters, and interactive terminal input utilities directly from Core\Command:

PHP 
<?php

namespace Command;

use Core\Command;
use Core\DB;
use Core\Mailer;

class SendWeeklyDigest extends Command
{
    /**
     * The command signature / CLI trigger name.
     */
    public string $name = 'send-weekly-digest';

    /**
     * Brief description shown in help and listings.
     */
    public string $description = 'Send weekly newsletter and digest to active subscribers';

    /**
     * Execute the command logic.
     *
     * @param array $args Command line arguments passed after the command name.
     * @return int Exit code (0 for success, non-zero for error)
     */
    public function execute(array $args): int
    {
        $this->info("Running SendWeeklyDigest...");

        // Query database via DB or Model
        $subscribers = DB::table('users')->where('subscribed', 1)->get();
        $this->line("Found " . count($subscribers) . " subscribers.");

        // Built-in output and interaction helpers:
        // $this->info("text");          // Cyan informational message
        // $this->success("text");       // Green success message
        // $this->warning("text");       // Yellow warning message
        // $this->error("text");         // Red error message
        // $this->line("text");          // Standard line
        // $this->table($headers, $rows); // Formatted ASCII data table
        // $this->confirm("Are you sure?", false); // Interactive confirmation
        // $this->ask("Enter parameter:", "default"); // Interactive prompt

        $this->success("SendWeeklyDigest finished successfully!");
        return 0;
    }
}

3. Running Custom Commands via Terminal

Execute your command using either the command signature, the class name, or the explicit run keyword:

Bash 
# Run by trigger signature
srin send-weekly-digest

# Or run by class name
srin SendWeeklyDigest

# Using explicit run
srin run send-weekly-digest

# List all registered custom commands in Command/
srin commands

4. Setting up in cPanel Cron Jobs

To automate your command on a recurring schedule in cPanel:

  1. Log into your cPanel dashboard.
  2. Scroll to Advanced and click Cron Jobs.
  3. Under Add New Cron Job, pick your schedule from the Common Settings dropdown (e.g. Once Per Day (0 0 * * *) or Every Hour (0 * * * *)).
  4. In the Command field, paste either of the following commands:
cPanel Cron Job (Absolute Path) 
/usr/local/bin/php /home/YOUR_CPANEL_USER/public_html/srin send-weekly-digest >/dev/null 2>&1

Or if using directory navigation:

cPanel Cron Job (cd Directory) 
cd /home/YOUR_CPANEL_USER/public_html && /usr/local/bin/php srin send-weekly-digest >/dev/null 2>&1

Why >/dev/null 2>&1?

cPanel sends an email to the account owner whenever a cron job outputs text to standard output or standard error. Adding >/dev/null 2>&1 discards routine output and prevents your inbox from being spammed on every execution.

To save output to a log file on your server for auditing or debugging, redirect output to a log file instead:

/usr/local/bin/php /home/YOUR_CPANEL_USER/public_html/srin send-weekly-digest >> /home/YOUR_CPANEL_USER/public_html/Others/logs/cron.log 2>&1
