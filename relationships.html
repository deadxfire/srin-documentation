Relationships & Eager Loading

Real-world web applications depend on interconnected data. Srin Engine provides intuitive model relationships—including hasMany, belongsTo, and hasOne—coupled with eager loading to eliminate the infamous N+1 query performance bottleneck.

Defining Relationships

One to Many: hasMany

An author or post has many comments. Define this relation by returning $this->hasMany():

PHP (Model/Post.php) 
namespace Model;

use Core\Model;

class Post extends Model
{
    /**
     * Get all comments for this blog post.
     */
    public function comments()
    {
        return $this->hasMany(Comment::class);
    }
}

Inverse Relation: belongsTo

To navigate backward from a comment to its parent post or author, define a belongsTo relationship:

PHP (Model/Comment.php) 
namespace Model;

use Core\Model;

class Comment extends Model
{
    /**
     * Get the post that owns this comment.
     */
    public function post()
    {
        return $this->belongsTo(Post::class);
    }

    /**
     * Get the user author of this comment.
     */
    public function author()
    {
        return $this->belongsTo(User::class, 'user_id');
    }
}

One to One: hasOne

For singular relations like a user profile or account settings:

PHP (Model/User.php) 
namespace Model;

use Core\Model;

class User extends Model
{
    public function profile()
    {
        return $this->hasOne(Profile::class);
    }
}

Accessing Related Models

Once defined, access related models as dynamic object properties:

PHP 
$post = Post::find(1);

// Access comments as array of Comment models
foreach ($post->comments as $comment) {
    echo $comment->content;
}

// Access parent model
$comment = Comment::find(5);
echo $comment->post->title;

Eager Loading: Solving the N+1 Query Problem

When looping over 50 posts and reading each post's comments without eager loading, the application executes 1 query for the posts + 50 queries for each comment set (51 database queries total).

With Srin Engine's with() eager loading, this is reduced to just 2 queries regardless of whether you display 10 or 1,000 posts:

PHP 
// Executes exactly 2 optimized SQL queries:
// 1. SELECT * FROM posts WHERE is_published = 1
// 2. SELECT * FROM comments WHERE post_id IN (1, 2, 3, ...)
$posts = Post::where('is_published', true)
    ->with('comments')
    ->get();

Eager Loading Multiple Relations

PHP 
$posts = Post::with(['comments', 'author', 'tags'])->latest()->paginate(10);

Lazy Eager Loading: load()

If you already have a model instance and want to eager-load relations on demand:

PHP 
$post = Post::find(1);

if ($needComments) {
    $post->load('comments');
}
