Security & Defense-in-Depth

Security is not an afterthought in Srin Engine—it is woven directly into every layer of the core. With automatic CSRF tokens, anti-spam honeypot traps, built-in rate limiting, null-byte sanitization, and mass-assignment protection, your application is hardened by default.

The 8 Pillars of Srin Security

🔐
CSRF Protection
Cryptographically secure session tokens validated using timing-attack safe hash_equals().
🐝
Anti-Bot Honeypot
Transparent anti-spam traps that trick automated bots without annoying human users with CAPTCHAs.
⏱
Rate Limiting
IP-based throttling protecting login forms and sensitive API endpoints against brute-force attacks.
🛡
XSS Neutralization
Automatic HTML entity escaping via [[ $var ]] preventing malicious script injection.
🔑
Mass Assignment Defense
Model-level $fillable whitelists and controller-level $this->onlyInputs().

Automatic stripping of null bytes (\0), control characters, and CRLF header splitting.

Memory-hard password hashing (RFC 9106) resisting GPU/ASIC cracking with auto-rehashing and peppering.
🔒
AES-256-GCM AEAD
Hardware-accelerated authenticated symmetric encryption with automatic tamper and corruption detection.

1. Cross-Site Request Forgery (CSRF)

Every POST, PUT, or DELETE form should include the <?= csrf_field() ?> directive. This embeds a hidden token validated against the user's active session:

HTML / Srin Template 
<form method="POST" action="[[ route('contact.submit') ]]">
    [csrf]
    <input type="text" name="name" required>
    <button type="submit">Send</button>
</form>

In your controller, verify the token with one method call:

PHP (Controller) 
public function submit(): void
{
    // Aborts with HTTP 419 Page Expired if missing or invalid
    $this->validateCsrf();

    // Process safe form...
}

AJAX & JavaScript CSRF Headers

When making asynchronous JavaScript Fetch or Axios requests, pass the CSRF token in the request headers:

JavaScript 
fetch('/api/cart/add', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        'X-CSRF-TOKEN': '<?= csrf_token() ?>'
    },
    body: JSON.stringify({ item_id: 42 })
});

2. Anti-Bot Honeypot Traps

CAPTCHAs create friction for genuine users and hurt conversion rates. Srin Engine features a built-in Honeypot Trap:

HTML / Srin Template 
<form method="POST" action="[[ route('newsletter.signup') ]]">
    [csrf]
    [honeypot]

    <input type="email" name="email" placeholder="Your email" required>
    <button type="submit">Subscribe</button>
</form>

The [honeypot] directive inserts an invisible input field styled off-screen. Real human users cannot see it and leave it empty. Automated spam scripts blindly fill all inputs. Validate it in your controller:

PHP 
// Aborts with HTTP 400 Bad Request if field contains content
$this->validateHoneypot();

3. Rate Limiting (Throttle)

Prevent brute-force password cracking and form spam by throttling requests based on client IP:

PHP 
public function login(): void
{
    // Limit to 5 attempts per 60 seconds
    $this->rateLimit('login-attempt', maxAttempts: 5, decaySeconds: 60);

    // Continue authentication...
}
Automatic 429 Too Many Requests

If the user exceeds the specified attempt threshold within the decay window, Srin halts execution immediately and renders Pages/errors/429.srin.php.

4. Mass Assignment Whitelisting

Never pass unfiltered raw request arrays directly to model creation or updates:

PHP 
// VULNERABLE: A malicious user could send 'is_admin' => 1
// User::create($this->allInputs());

// SECURE: Whitelist only permitted attributes
$safeData = $this->onlyInputs(['name', 'email', 'bio']);
User::create($safeData);

6. Secure File & Image Uploads

File uploads represent one of the most critical attack vectors in web applications (remote code execution via uploaded PHP scripts, overwriting system files, or denial of service). Srin Engine provides built-in defenses against these vectors:

PHP (Controller) 
// 1. Verify valid upload (defeats empty-file false positives)
if ($this->hasFile('avatar')) {
    // 2. Enforce strict extension whitelist + randomized collision-safe filename
    $path = $this->storeFile('avatar', 'assets/uploads', ['jpg', 'png', 'webp']);
    
    if (!$path) {
        return $this->fail('Invalid or prohibited file type.')->back();
    }
}
Three-Tier Upload Defense
  • Strict Error Code Verification: hasFile() ensures $_FILES['key']['error'] === UPLOAD_ERR_OK and verifies tmp_name is non-empty, preventing empty-upload bypasses.
  • Cryptographic Filename Hashing: storeFile() replaces user-supplied filenames with bin2hex(random_bytes(16)), preventing directory traversal (../../etc/passwd) and double-extension tricks (exploit.php.jpg).
  • Strict Extension Whitelisting: Passing ['jpg', 'png', 'webp'] strictly verifies the file extension before moving it, blocking malicious scripts from being uploaded to public directories.

7. Authentication & Identity Management (Core\Auth)

Srin Engine provides an enterprise-grade, zero-dependency authentication manager (Core\Auth) featuring memory-hard password hashing, application-level peppering, automatic hash upgrades, credential verification, and session fixation defense.

Advanced Password Hashing with Argon2id (RFC 9106)

Traditional hashing algorithms (such as MD5, SHA-256, or unconfigured Bcrypt) are vulnerable to modern GPU and ASIC hardware-accelerated dictionary attacks. Srin Engine defaults to Argon2id (PASSWORD_ARGON2ID)—the winner of the Password Hashing Competition (PHC) and recommended standard by OWASP.

Why Argon2id?

Argon2id is a hybrid of Argon2d and Argon2i. It provides maximum resistance against side-channel cache-timing attacks while remaining memory-hard, making GPU-based offline password cracking economically infeasible.

Authentication Configuration (Config/auth.php)

Fine-tune your password hashing parameters, memory limits, iteration counts, application pepper, and fallback algorithms:

PHP (Config/auth.php) 
return [
    'model' => env('AUTH_MODEL', \Model\Account::class),
    'identifier' => env('AUTH_IDENTIFIER', 'email'),
    'password_column' => 'password',

    // Password Hashing & Encryption Engine
    'hash' => [
        // Primary algorithm: 'argon2id', 'argon2i', 'bcrypt', or 'default'
        'algorithm' => env('AUTH_HASH_ALGO', 'argon2id'),

        // RFC 9106 recommended parameters (secure & lightweight)
        'argon2id' => [
            'memory_cost' => (int) env('AUTH_ARGON_MEMORY', 65536), // 64 MB
            'time_cost'   => (int) env('AUTH_ARGON_TIME', 3),       // 3 iterations
            'threads'     => (int) env('AUTH_ARGON_THREADS', 1),     // 1 execution thread
        ],

        // Bcrypt fallback configuration
        'bcrypt' => [
            'cost' => (int) env('AUTH_BCRYPT_COST', 12),
        ],

        // Secret Application Pepper (Keyed Hashing Salt)
        'pepper' => env('AUTH_PEPPER', ''),

        // Automatic zero-downtime hash upgrades upon user login
        'auto_rehash' => (bool) env('AUTH_AUTO_REHASH', true),
    ],
];

Application Pepper (Defense-in-Depth)

Srin Engine supports optional application-level peppering via AUTH_PEPPER. When configured, plain passwords are keyed using HMAC-SHA256 prior to Argon2id hashing:

INI / .env 
AUTH_HASH_ALGO=argon2id
AUTH_ARGON_MEMORY=65536
AUTH_ARGON_TIME=3
AUTH_PEPPER=your-ultra-secret-application-pepper-string

Even if an attacker gains full read access to your SQL database dump, the password hashes cannot be brute-forced offline without the secret AUTH_PEPPER key located outside the database in your server environment.

Zero-Downtime Automatic Rehashing

When existing users log in via Auth::attempt(), Srin automatically checks if their stored hash was created with an older algorithm (such as legacy Bcrypt) or with older cost/pepper parameters. If an upgrade is needed, Srin automatically rehashes the password using the current Argon2id configuration and updates the database record silently—without user disruption.

Handling Authentication in Controllers

PHP (Controller) 
namespace Controller;

use Core\BaseController;
use Core\Auth;
use Model\Account;

class AuthController extends BaseController
{
    public function register()
    {
        $data = $this->guard([
            'name'     => 'required|min:3',
            'email'    => 'required|email',
            'password' => 'required|min:8|confirmed',
        ]);

        // Create account with powerful Argon2id hash
        $user = Account::create([
            'name'     => $data['name'],
            'email'    => $data['email'],
            'password' => Auth::hash($data['password']), // or hash_password($data['password'])
        ]);

        Auth::login($user);
        return $this->success('Account created successfully!')->go('dashboard');
    }

    public function login()
    {
        // 1. Guard inputs (enforces CSRF and rate limiting)
        $data = $this->guard([
            'email'    => 'required|email',
            'password' => 'required',
        ]);

        // 2. Attempt authentication (auto-verifies and auto-rehashes to Argon2id)
        if (Auth::attempt($data['email'], $data['password'])) {
            return $this->success('Welcome back, ' . Auth::user()->name . '!')
                ->go('dashboard');
        }

        return $this->fail('Invalid email or password.')->back();
    }

    public function logout()
    {
        Auth::logout();
        return $this->success('You have been signed out.')->go('home');
    }
}

8. High-Performance Authenticated Encryption (Core\Crypt)

For sensitive data that requires two-way reversible encryption (e.g., third-party API credentials, OAuth access tokens, private keys, or encrypted form fields), Srin Engine provides Core\Crypt—a lightweight, military-grade symmetric cipher built directly on AES-256-GCM (Galois/Counter Mode).

🔒
AES-256-GCM
Hardware-accelerated AES-256 cipher delivering sub-millisecond execution with negligible CPU overhead.
🛡
AEAD Authentication
128-bit authentication tag guarantees ciphertext integrity; any forged or corrupted payload is instantly rejected.
🎲
Dynamic 96-Bit Nonce
Cryptographically random 12-byte IV per encryption prevents replay attacks and identical ciphertexts.
🔗
URL-Safe Base64
Packed IV + Tag + Ciphertext format is safe for HTTP query parameters, headers, cookies, and database columns.

Generating the Application Encryption Key

Run the Srin CLI command to generate a cryptographically secure 256-bit key in your .env file:

Bash 
php srin key:generate

Encrypting & Decrypting Sensitive Data

PHP 
use Core\Crypt;

// 1. Encrypt plaintext using Core\Crypt
$encrypted = Crypt::encrypt('sk_live_51Msz...super_secret_api_key');

// Or use global helper:
$encrypted = encrypt('my-secret-token');

// 2. Decrypt payload (returns null if corrupted or tampered)
$decrypted = Crypt::decrypt($encrypted);

// Or use global helper:
$decrypted = decrypt($encrypted);

if ($decrypted === null) {
    // Payload was modified, forged, or encrypted with a different key
    abort(400, 'Tampered cryptographic payload detected.');
}
