Assets & Image Linking

In Srin Engine, static asset management is seamless. The http://localhost:8000/assets/ helper generates direct, fully qualified web URLs (e.g. https://example.com/assets/images/photo.png) rather than local filesystem paths, with built-in subfolder detection, reverse-proxy SSL normalization, and automatic image folder mapping.

The Direct Asset Link Superpower

When working in views, you shouldn't have to worry about whether your application is hosted in a root domain, a nested subfolder (e.g., /app/v2/), or behind an SSL terminating reverse proxy.

Srin Engine's http://localhost:8000/assets/ helper automatically resolves the complete, direct web link:

HTML / Srin Template 
<!-- Pass an image filename directly -->
<img src="http://localhost:8000/assets/images/logo.png" alt="Srin Engine Logo">

<!-- Output rendered by the browser: -->
<!-- <img src="http://localhost:8000/assets/images/logo.png" alt="Srin Engine Logo"> -->
Automatic Image Folder Resolution

Notice how you don't even need to type images/logo.png! If you pass an image extension (such as .png, .jpg, .svg, .webp, .avif), Srin automatically maps the link into the assets/images/ folder.

Asset URL Resolution Matrix

Code Resolved URL Output Behavior Description
http://localhost:8000/assets/images/avatar.jpg http://localhost:8000/assets/images/avatar.jpg Auto-maps image extension to assets/images/.
http://localhost:8000/assets/images/banner.webp http://localhost:8000/assets/images/banner.webp Preserves explicit category directory.
http://localhost:8000/assets/css/app.css http://localhost:8000/assets/css/app.css Maps stylesheet to CSS directory.
http://localhost:8000/assets/js/app.js?v=2.1 http://localhost:8000/assets/js/app.js?v=2.1 Preserves cache-busting query strings.
https://cdn.example.com/font.woff2 https://cdn.example.com/font.woff2 External CDN URLs are returned untouched.
http://localhost:8000/assets/ http://localhost:8000/assets/ Returns the base public asset directory URL.

Recommended Asset Directory Structure

Organize your static files inside the root assets/ or Public/assets/ folder:

Directory Structure 
assets/
├── css/
│   ├── app.css
│   └── components.css
├── js/
│   ├── app.js
│   └── tracker.js
├── images/
│   ├── favicon.svg
│   ├── logo.png
│   └── banner.webp
├── fonts/
│   └── inter.woff2
└── downloads/
    └── user_guide.pdf

Secure Asset Downloads via Controllers

To serve protected or downloadable files to users without exposing your filesystem or internal template directories, use the controller's $this->download() method:

PHP (Controller/DocumentController.php) 
public function downloadInvoice(string $id): void
{
    // Verify user authorization...
    $filename = "invoices/inv_{$id}.pdf";

    // Streams secure download with custom filename
    $this->download($filename, "My_Invoice_{$id}.pdf");
}
Directory Traversal Defense

$this->download() strictly validates paths against the assets/ folder. Any attempt to use dot-dot sequences (../Pages/index.srin.php or ../.env) is immediately blocked with an HTTP 403 Forbidden exception.

Managing User Uploads & Media

User-uploaded images (such as avatars, blog thumbnails, or PDF attachments) are typically stored within the assets/uploads/ directory. Because they reside within assets/, they can be directly referenced by Srin's asset URL helpers:

PHP / Srin Template 
<!-- Controller: Storing an uploaded profile photo -->
$imagePath = $this->storeFile('avatar', 'assets/uploads', ['jpg', 'png', 'webp']);

// Stored path returned: "assets/uploads/4f9e8a1c...png"
$user->avatar = $imagePath;
$user->save();

<!-- View: Rendering the uploaded photo in HTML -->
<img src="<?= assets($user->avatar) ?>" alt="Profile Picture" class="avatar-img">
Upload Security Best Practices
  • Randomized Filenames: Never preserve raw user-supplied filenames directly on disk. $this->storeFile() automatically generates a cryptographically random 32-character hex name to prevent overwrites and script execution attacks.
  • Extension Whitelisting: Always pass an allowed extension array (e.g. ['jpg', 'png', 'webp', 'pdf']) to prohibit malicious executable files (like .php or .phtml).
  • Automated Directory Creation: If the destination folder does not exist, $this->storeFile() automatically creates it with secure 0755 permissions.
