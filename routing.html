Routing & Named Routes

Srin Engine features a lightning-fast, expressive HTTP router. Define web routes in Routes/web.php and stateless API routes in Routes/api.php with support for named routes, URI parameters, and route inspection.

Basic Route Link Registration

Routes are registered in Routes/web.php using Srin's expressive Route Link functions (getlink(), postlink(), etc.) or the fluent Core\Link facade. Handlers accept a Closure, a controller string (Controller@action), or an array ([Controller::class, 'action']):

PHP (Routes/web.php) 
use Core\Link;
use Controller\HomeController;
use Controller\BlogController;

// Simple closure link
getlink('/', function() {
    return 'Welcome to Srin Engine!';
});

// Controller action using Class string
getlink('/about', 'HomeController@about');

// Controller action using Array syntax
getlink('/blog', [BlogController::class, 'index']);

// Fluent OOP Link facade
Link::get('/pricing', 'PricingController@index');

Available Route Link Methods

The Link engine supports all standard HTTP verbs:

PHP 
getlink($uri, $action);
postlink($uri, $action);
putlink($uri, $action);
patchlink($uri, $action);
deletelink($uri, $action);
optionslink($uri, $action);
anylink($uri, $action); // Matches any HTTP verb

// Or via Core\Link facade:
Link::get($uri, $action);
Link::post($uri, $action);
Link::put($uri, $action);
Link::patch($uri, $action);
Link::delete($uri, $action);
Link::options($uri, $action);
Link::any($uri, $action);

Route Parameters

Capture URI segments by wrapping parameter names in curly braces {param}. Srin automatically passes captured values to your controller method in the order they appear:

PHP 
// Single parameter
getlink('/users/{id}', 'UserController@show');

// Multiple parameters
getlink('/posts/{category}/{slug}', 'PostController@show');

Inside your controller action, type-hint the incoming parameters:

PHP (Controller/PostController.php) 
public function show(string $category, string $slug): string
{
    $post = Post::where('category', $category)
        ->where('slug', $slug)
        ->firstOrFail();

    return $this->view('posts/show', ['post' => $post]);
}

Named Routes & URL Generation

Naming your routes makes URL generation effortless and immune to path refactoring. Srin Engine supports both direct 3rd-argument naming (clean Srin style) and method chaining:

PHP 
// Direct 3rd-parameter naming (Srin signature style)
getlink('/articles', 'ArticleController@index', 'articles.index');
postlink('/articles', 'ArticleController@store', 'articles.store');

// Or fluent chaining with ->name()
getlink('/checkout', 'CartController@checkout')->name('cart.checkout');

Generating URLs with the route() Helper

Use the global route() helper in PHP code or [[ route('name') ]] in your .srin.php view templates:

HTML / Srin Template 

<a href="[[ route('cart.checkout') ]]">Proceed to Checkout</a>


<a href="[[ route('docs.show', ['topic' => 'routing']) ]]">Read Routing Docs</a>


$url = route('docs.show', ['topic' => 'routing']);

Route-Aware Navigation Helpers

Highlighting active navigation tabs in your navbar is built-in:

HTML / Srin Template 
<nav>
    <a href="[[ route('home') ]]" class="<?= is_home() ? 'active' : '' ?>">Home</a>
    <a href="[[ route('blog.index') ]]" class="<?= is_route('blog.index') ? 'active' : '' ?>">Blog</a>
    <a href="[[ route('docs') ]]" class="<?= is_route_active('docs.*') ? 'active' : '' ?>">Documentation</a>
</nav>
Tip: Inspecting Routes via CLI

Run php srin routes at any time in your terminal to see all registered routes, HTTP methods, and their associated controller actions.

Checkpoints: The Clean Middleware Alternative

Instead of bloated, recursive closure chains and complex onion pipelines, Srin Engine introduces Checkpoints—linear request verification gates with an intuitive enter() and leave() lifecycle.

1. Attaching Checkpoints to Routes

Secure any route by chaining the ->checkpoint() method:

PHP (Routes/web.php) 
// Single checkpoint
getlink('/dashboard', 'DashboardController@index', 'dashboard')
    ->checkpoint('auth');

// Multiple checkpoints
getlink('/admin/reports', 'AdminController@reports', 'admin.reports')
    ->checkpoint(['auth', 'admin']);

2. Route Groups with Checkpoints & Prefixes

Bundle protected routes together using grouplink() (or Link::group()):

PHP (Routes/web.php) 
grouplink(['prefix' => '/dashboard', 'checkpoint' => 'auth'], function () {
    getlink('/', 'DashboardController@index', 'dashboard');
    getlink('/profile', 'DashboardController@profile', 'dashboard.profile');
    postlink('/avatar', 'DashboardController@uploadAvatar', 'dashboard.avatar');
});

3. Built-In Checkpoints

Alias Class Behavior Description
'auth' Checkpoint\AuthCheckpoint Requires visitor to be signed in. Redirects unauthenticated guests to login.
'guest' Checkpoint\GuestCheckpoint Requires visitor to be a guest. Redirects already authenticated users away from login/register.
'admin' Checkpoint\AdminCheckpoint Requires signed-in account with administrator privileges. Aborts with HTTP 403 Forbidden if not admin.

4. Creating Custom Checkpoints

Scaffold a custom checkpoint gate using the CLI:

Bash 
php srin make:checkpoint VerifySubscription

Unlike confusing recursive pipelines where forgetting to return the response breaks the app, Srin Checkpoints are clear and linear:

PHP (Checkpoint/VerifySubscriptionCheckpoint.php) 
namespace Checkpoint;

use Core\Checkpoint;
use Core\Auth;

class VerifySubscriptionCheckpoint extends Checkpoint
{
    /**
     * Inspect request before controller runs.
     * Return true (or null) to ALLOW passage.
     * Return a redirect, Response, or false to HALT.
     */
    public function enter(): mixed
    {
        if (!Auth::user()->isSubscribed()) {
            flash('warning', 'Please activate your subscription to access this feature.');
            redirect('/billing/plans');
            return false;
        }

        return true;
    }
}
